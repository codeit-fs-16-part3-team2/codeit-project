백엔드 이슈는 API·데이터·거래 규칙을, 프론트엔드 이슈는 화면·상태 표시·API 연결을 다룬다. 팀 정책 결정과 배포 통합 검증은 공통 이슈로 둔다. 담당자는 팀이 배정한다.

프론트엔드는 [API 계약의 응답 형식](api.md#응답-필드)에 맞춘 mock으로 바로 시작한다. 다른 화면과 이어지는 경우에는 먼저 개별 화면을 작업하고, 화면이 준비되면 이동 흐름을 연결한다. 미정인 입력 정책은 확정 후 화면 검증에 반영한다.

각 프론트엔드 이슈의 ‘실제 API 연결·검증’은 화면 개발을 마친 뒤 확인하는 단계다. mock으로 화면과 오류 표시를 먼저 검증하고, 실제 API로 교체해 완료 기준을 다시 확인한다. 배포 시연과 최종 통합은 실제 API를 사용한다.

### 백엔드

#### P0-BE-01 · Express·PostgreSQL 기반과 시드 준비

선행 이슈 `P0-COMMON-01`.

- [ ] Express 5에서 라우터·컨트롤러·서비스·저장소의 책임을 나누고 공통 성공·실패 응답을 적용한다.
- [ ] Prisma 7 검증과 빈 개발 DB 마이그레이션을 통과한다. 수량·잔액·가격 범위 제약을 확인하고 구매 수량 0과 음수 잔액은 저장할 수 없음을 검증한다.
- [ ] 시드 판매자가 판매 가능한 같은 카드 세 장 이상을 보유한다. 시드를 반복 실행해도 카드와 보유 수량이 중복되지 않는다.
- [ ] Render의 Express API가 PostgreSQL에 연결된다.

#### P0-BE-02 · 가입·로그인·로그아웃과 세션 API

선행 이슈 `P0-COMMON-01`, `P0-BE-01`.

- [ ] 가입 시 회원과 10P 지급 내역이 한 번만 생성되고, 발급된 세션으로 `/api/me`를 조회할 수 있다. 중복 이메일·닉네임과 잘못된 로그인 정보는 계약대로 거절한다.
- [ ] 세션은 발급 후 24시간에 만료되고, 로그아웃한 세션은 재사용할 수 없다.
- [ ] 세션이 없는 회원 전용 요청과 허용 출처가 아닌 상태 변경 요청을 계약대로 거절한다.

#### P0-BE-03 · 판매 목록·상세·등록과 갤러리 기본 API

선행 이슈 `P0-BE-02`.

- [ ] 회원은 판매 목록과 상세를 조회하며, 두 응답에서 같은 판매글의 가격과 잔여 수량이 일치한다.
- [ ] 회원은 자신의 보유 카드만 조회·판매 등록할 수 있다. 장당 0P를 허용하고 거래 가능 수량 초과를 거절한다.
- [ ] 보유 카드 세 장을 모두 등록하면 판매 잔여는 세 장이고, 갤러리 응답에서 판매 중인 세 장은 제외된다.

#### P0-BE-04 · 여러 장 구매와 포인트·재고 처리

선행 이슈 `P0-BE-03`.

- [ ] 구매 수량과 당시 장당 가격, 양쪽 보유 수량, 판매 잔여 수량, 포인트 잔액과 내역을 하나의 트랜잭션에서 처리한다. 0P 구매는 구매 내역과 소유권을 반영하고 포인트 잔액을 유지한다.
- [ ] 자기 판매글 구매, 포인트 부족, 재고 부족, 가격 변경은 계약대로 실패하고 수량·잔액은 그대로다.
- [ ] 마지막 한 장에 동시 구매 요청 두 건을 보내면 한 건만 성공하고, 판매 잔여가 0이 되어 품절로 조회된다.

### 프론트엔드

#### P0-FE-01 · Next.js 랜딩·인증 화면과 접근 제어

- **Mock으로 먼저 작업.** 비로그인·로그인 상태, 가입 직후 10P, 중복 가입, 로그인 실패, 세션 만료 응답으로 화면 전환과 오류를 확인한다. 브라우저 쿠키와 세션 만료는 실제 API 연결 후 검증한다.
- **정책 확정 후 반영.** `P0-COMMON-01`의 결과를 입력·표시 검증에 반영한다.
- **실제 API 연결·검증.** `P0-BE-02`의 API가 준비되면 mock을 실제 응답으로 교체해 아래 기준을 확인한다.

- [ ] 비로그인 사용자는 랜딩·회원가입·로그인 화면을 이용한다. 마켓플레이스나 개인 목록 URL에 직접 접속해도 회원 데이터가 표시되지 않는다.
- [ ] 가입·로그인에 성공하거나 로그인한 상태로 첫 화면을 열면 마켓플레이스로 이동한다.
- [ ] 오류를 확인하고 다시 시도할 수 있다. 로그아웃하거나 세션이 만료되면 회원 화면에서 거래할 수 없다.

#### P0-FE-02 · 마켓플레이스·판매 등록·마이 갤러리 기본 화면

- **Mock으로 먼저 작업.** 판매 가능한 카드 3장, 빈 갤러리, 판매 목록과 상세, 등록 성공·실패 응답으로 흐름을 확인한다.
- **화면 연결.** `P0-FE-01`와 이동 흐름을 확인한다.
- **실제 API 연결·검증.** `P0-BE-03`의 API가 준비되면 mock을 실제 응답으로 교체해 아래 기준을 확인한다.

- [ ] 판매 목록에서 상세를 열 수 있다. 마켓플레이스와 마이 갤러리에서 판매 등록으로 이동해 카드와 수량을 고를 수 있다.
- [ ] 판매 등록 성공·실패 화면에서 결과를 확인하고 마켓플레이스로 돌아갈 수 있다.
- [ ] 마이 갤러리에서 현재 보유 카드와 표시 수량을 확인할 수 있다.

#### P0-FE-03 · 판매 상세의 구매와 결과 표시

- **Mock으로 먼저 작업.** 2장 구매 성공 후 잔액 2P와 판매 잔여 1장, 포인트 부족·재고 부족·가격 변경 응답으로 결과 화면을 확인한다.
- **화면 연결.** `P0-FE-02`와 이동 흐름을 확인한다.
- **실제 API 연결·검증.** `P0-BE-04`의 API가 준비되면 mock을 실제 응답으로 교체해 아래 기준을 확인한다.

- [ ] 판매 상세에서 등록자 여부에 맞는 동작을 보여준다. 구매자는 같은 주소에서 수량과 결제액을 확인하고 성공·실패 결과를 볼 수 있다.
- [ ] 구매자가 마이 갤러리에서 구매한 카드를 확인한다. 판매 목록이나 상세를 다시 열면 줄어든 잔여 수량이 표시된다.

### 백엔드

#### P1-BE-01 · 판매 수정·취소와 재고 복구 API

선행 이슈 `P0-BE-03`.

- [ ] 등록자는 가격과 교환 희망 정보만 수정할 수 있다. 수량 변경과 타인의 수정·취소는 거절한다.
- [ ] 취소한 판매글은 목록에서 빠지고 잔여 수량은 다시 거래에 쓸 수 있다. 이미 취소되거나 품절된 판매글의 요청은 계약대로 처리한다.

#### P1-BE-02 · 교환 제안·응답과 거래 처리 API

선행 이슈 `P0-BE-04`, `P1-BE-01`.

- [ ] 다른 회원의 판매글에 보유 카드 한 장을 제안할 수 있다. 희망 조건과 다른 카드도 제안할 수 있고 대기 중인 카드는 다른 거래에 쓸 수 없다.
- [ ] 판매자는 받은 제안만, 제안자는 본인이 보낸 제안만 조회한다. 등록자는 받은 대기 제안을 승인·거절하고 제안자는 본인의 대기 제안을 취소할 수 있다. 권한이 없거나 종료된 제안 처리 요청은 거절한다.
- [ ] 승인하면 양쪽 카드 한 장씩과 판매 잔여 수량이 한 번만 바뀐다. 거절·제안 취소·판매 취소·품절 후 대기 카드 수량은 다시 거래 가능해진다.
- [ ] 마지막 한 장을 구매와 교환 승인이 동시에 사용하려 하면 한 건만 성공한다. 판매 취소나 품절 시 남아 있는 대기 제안은 자동 종료된다.

#### P1-BE-03 · 마켓플레이스 검색·필터·정렬·커서 API

선행 이슈 `P0-BE-03`.

- [ ] 카드 이름 검색, 등급·장르·설명·매진 여부 중 하나의 필터, 최신순·오래된순·낮은 가격순·높은 가격순이 계약대로 동작한다.
- [ ] 정렬 값이 같은 항목도 목록이 바뀌지 않는 동안 커서로 중복·누락 없이 조회한다. 마지막 응답의 `nextCursor`는 `null`이다.

#### P1-BE-04 · 마이 갤러리 검색·필터·정렬·페이지 API

선행 이슈 `P0-BE-03`, `P1-BE-02`, `P1-COMMON-01`.

- [ ] 본인의 보유 카드만 검색·필터·정렬·페이지 번호로 조회할 수 있다. 정렬 결과는 합의한 예시와 일치한다.
- [ ] 판매 수량을 갤러리 표시 수량에서 빼고 교환 대기 수량은 포함한다. 교환 대기 수량은 거래 가능 수량에서 뺀다.

#### P1-BE-05 · 나의 판매 포토카드 목록 API

선행 이슈 `P1-BE-01`, `P1-BE-02`.

- [ ] 회원 본인의 판매 등록과 보낸 대기 제안을 반환한다. 판매 중·교환 제안 대기 중·품절을 구분하고 동일 카드의 판매 수량과 대기 수량을 별도 항목으로 반환한다.
- [ ] 등급·장르·판매 방법·매진 여부 필터와 페이지 번호 조회가 동작한다.

#### P1-BE-06 · 브리프의 거래 알림 생성·조회 API

선행 이슈 `P0-BE-04`, `P1-BE-02`.

- [ ] 교환 제안 도착·판매 성사·품절을 판매자에게, 승인·거절을 제안자에게, 구매 완료를 구매자에게 저장한다. 해당 수신자만 조회할 수 있다.
- [ ] 마지막 수량 소진 시 품절 알림은 한 번만 생성된다. 실패한 거래에는 완료 알림이 생기지 않는다.

#### P1-BE-07 · 랜덤 상자 상태와 적립 API

선행 이슈 `P0-BE-02`.

- [ ] 가입 직후 처음 열 수 있으며 1P부터 5P까지의 확률은 각각 40%·25%·18%·12%·5%다. 각 보상 구간의 시작과 끝을 검증한다.
- [ ] 마지막 개봉 후 한 시간 미만이면 거절하고 한 시간이 되면 다시 열 수 있다. 같은 회원의 동시 요청은 한 건만 적립된다.
